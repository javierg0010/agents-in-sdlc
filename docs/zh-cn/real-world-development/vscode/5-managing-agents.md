使用代理模式时，GitHub Copilot 会自主探索代码库、提出更改、编辑文件并运行命令。由于这些工作实时发生在本机，VS Code 中的 Copilot Chat 会显示每次工具调用和文件编辑。你可以查看每项差异、逐项接受或拒绝更改，也可以通过后续提示引导对话，在不离开编辑器的情况下完善或扩展工作。

本练习将：

- 实时监控无障碍智能体的工作；
- 审查并接受建议的文件编辑；
- 在会话进行期间引导智能体，在高对比度模式之外添加亮色模式切换。

## 场景

[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队又提出一项需求：为觉得默认主题太暗的用户添加亮色模式切换。你不必从头开始新对话，可以引导现有会话扩展工作范围。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每一步，包括探索的文件、运行的命令和建议的编辑。每项文件编辑都会在聊天中显示差异和 **Keep** / **Undo** 控件。

1. 返回练习 4 中打开的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天内容，查看每次工具调用。你会看到文件读取、文件编辑以及需要运行的终端命令。
3. 智能体提出文件编辑时，差异会直接显示在聊天中：
   - 选择 **Keep** 接受更改；
   - 选择 **Undo** 撤销更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的所有文件。

> [!NOTE]
> 如果工具调用需要权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式的实现。它会显示一条消息，总结所做的更改。

## 引导智能体添加亮色模式

高对比度模式完成后，在同一对话中扩展工作，添加亮色模式切换。继续使用同一聊天会话，智能体便会保留先前工作的上下文，包括修改的组件、样式方案和 local storage 模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得很好！现在请在高对比度切换旁边添加亮色模式切换。亮色模式应遵循相同模式：使用 local storage 保存设置，并在同一个 UI 区域中供用户使用。用户应能分别启用高对比度模式和亮色模式。
    ```

2. 智能体会继续之前的工作，检查已有更改并提出亮色模式的新增内容。
3. 像审查高对比度模式一样，逐项检查新编辑。使用 **Keep** 或 **Undo** 处理每项差异。
4. 如果智能体的处理方向不符合预期，例如试图以不喜欢的方式重构切换 UI，可以选择聊天输入框旁的 **Stop** 按钮停止，然后发送澄清后的后续消息。

> [!TIP]
> 引导进行中的会话比从头开始更快。可以使用后续提示要求调整（“简化 CSS，使用 CSS 变量而不是重复选择器”）、纠正方向（“不要增加第三个切换开关，将亮色模式集成到现有设置面板”），或扩展范围（“还为两个开关添加键盘快捷键”）。

## 审查工作文件

提交之前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 查看已更改文件的完整列表。应能看到 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改的文件并检查差异。确认其中体现了自定义智能体的无障碍模式，包括 ARIA 属性、键盘导航、语义化 HTML 和 local storage 持久化。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课将发布这些更改。

## 总结和后续步骤

你使用 Copilot Chat 代理模式监控并引导了一个正在进行的会话：逐项审查文件编辑、接受或拒绝更改，并通过后续提示扩展工作，同时保留上下文。

本课中你了解了：

- 如何实时监控智能体的工作；
- 如何接受和拒绝单个文件编辑；
- 如何通过后续提示引导进行中的会话。

在[下一课][next-lesson]中，你将把无障碍功能作为拉取请求发布，并审查本实验中本地自定义智能体所做的更改。
