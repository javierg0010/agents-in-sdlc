GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を適用または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整できます。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイルの編集をレビューして適用する。
- 作業中のエージェントに指示を追加し、ハイコントラストに加えてライトモードの切り替えを実装する。

## シナリオ

[Exercise 4][previous-lesson] で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を始める代わりに、現在のセッションの作業範囲を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調べたファイル、実行したコマンド、提案した編集など、各ステップを確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. Exercise 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を適用します。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッションで変更されたファイルをすべて確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止し、**Allow** を確認します。内容を確認して、許可してよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## ライトモードを追加するようエージェントに依頼する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットを続けることで、エージェントは以前の作業で触れたコンポーネント、スタイルの方法、local storage の使用パターンなどのコンテキストを保持します。

1. Copilot Chat の入力欄に次の追加プロンプトを送ります。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。それぞれの差分で **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合（たとえば切り替え UI を意図しない方法でリファクタリングしようとする場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を追加してから再度依頼します。

> [!TIP]
> 作業中のセッションを導く方が、最初からやり直すより短時間で済みます。追加プロンプトを使って、調整（「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」）、方向修正（「3つ目の切り替えを追加せず、ライトモードを既存の設定パネルに組み込む」）、範囲追加（「両方の切り替えにキーボードショートカットも追加する」）を依頼できます。

## 変更されたファイルを確認する

変更を commit する前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントで指定したアクセシビリティパターン（ARIA 属性、キーボード操作、セマンティック HTML、local storage への保存）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更を stage して commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、作業中のセッションを監視して方向付けました。各ファイルの編集を確認して適用または拒否し、コンテキストを失わずに追加プロンプトで作業範囲を広げました。

このレッスンでは、次の内容を学習しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を適用または拒否する。
- 追加プロンプトを使って作業中のセッションを調整する。
